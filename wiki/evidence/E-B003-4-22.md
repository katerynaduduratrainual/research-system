# Пакетна обробка запитів піднімає сумарну швидкість генерації Llama 3.1 8B на DGX Spark з 20,5 токена за секунду (один запит) до 368 (32 запити одночасно) (LMSYS, жовтень 2025)

## Контекст
Розділ «Overall Performance» огляду LMSYS Org. Llama 3.1 8B, FP8, рушій SGLang: batch 1 — 7 991 токен за секунду prefill / 20,5 decode; batch 32 — 7 949 / 368. Там само: спекулятивне декодування (EAGLE3, мала «чорнова» модель пропонує токени наперед) дало до 2× прискорення. Глосарій «токени за секунду»: число залежить від того, чи це швидкість одного потоку (що бачить один користувач), чи сумарна пропускна здатність за багатьох одночасних запитів (що важить для сервера); окремо міряють prefill (обробка вхідного запиту) і decode (генерація відповіді). Числа серверів у [[E-B003-4-24]] — сумарні, числа в [[E-B003-4-20]] — одного потоку; порівнювати їх напряму не можна.

## Цитата
> With SGLang at batch 1, it achieved 7,991 tps prefill / 20.5 tps decode, scaling up linearly to 7,949 tps / 368 tps at batch 32

## Верифікація
2026-10-08 — ok (жива сторінка): цитата дослівно в «Overall Performance»; Llama 3.1 8B у SGLang (у таблиці тестів — FP8): батч 1 — 7 991 / 20,5; батч 32 — 7 949 / 368 токенів за секунду (prefill / decode); «up to a 2× speed-up» для EAGLE3 підтверджено. 368 — сумарна швидкість за 32 одночасних запитів, тобто ≈11,5 токена за секунду на один запит (368 / 32); у claim це подано правильно як «сумарну».
