# Hooks детерміновано блокують дію Claude через exit-код, незалежно від рішення моделі

## Контекст
Hooks — shell-команди/скрипти, прив'язані до подій життєвого циклу Claude
Code (PreToolUse — перед виконанням інструменту, PostToolUse — після), що
виконуються автоматично без участі людини. Для PreToolUse: exit-код 2
блокує виклик інструменту, а stderr показується моделі як причина блокування
— це єдиний механізм у документації, що дає гарантоване (не імовірнісне)
обмеження дії агента, на відміну від інструкцій у CLAUDE.md/пам'яті, які є
лише контекстом (див. [[E-B002-6-10]]). Це прямий кандидат на реалізацію
"бюджету токенів"/лімітів у нашому pipeline — власний hook може рахувати
виклики інструментів чи витрачені токени і блокувати продовження при
перевищенні.

## Цитата
> "For a PreToolUse hook, exiting 2 blocks the tool call and the contents of stderr are surfaced to the model as the reason it was blocked."

## Верифікація
2026-09-11 — ok: цитата про exit-код 2, що блокує tool call для PreToolUse (навіть JSON permissionDecision:"allow" не може це перекрити), підтверджено дослівно. Grade виправлено C→B: задокументована функція офіційного продукту.

## Нотатки
Документація Claude Code сама протиставляє hooks і CLAUDE.md: "Claude treats
them as context, not enforced configuration. To block an action regardless
of what Claude decides, use a PreToolUse hook instead" (з S-2e02bd22) — це
офіційно задокументований поділ "порада моделі" vs "жорсткий контроль".
