# Routines у Claude Code виконуються без запиту дозволу, людина перевіряє вже після

## Контекст
Routine — збережена конфігурація (промпт + репозиторії + конектори), яка
виконується на хмарній інфраструктурі Anthropic за розкладом (hourly/
nightly/weekly), за API-викликом або на GitHub-подію. Мінімальний інтервал
розкладу — 1 година. Ключове для дизайну людських гейтів: під час запуску
немає жодного permission-picker чи approval-prompt — сесія отримує повний
доступ до інструментів, shell і конекторів одразу. Людський гейт
реалізований постфактум: кожен запуск створює окрему сесію/PR, яку людина
відкриває й перевіряє ("On-call reviews the PR instead of starting from a
blank terminal"); статус "green" означає лише що сесія відпрацювала без
інфраструктурної помилки, а не що завдання виконано правильно.
Профіль: автоматизує — весь нічний прогін (клонування репо, tool calls,
skills, конектори); людина в циклі — лише до (пише промпт заздалегідь) і
після (рев'ю сесії/PR), не під час; бюджети — денний ліміт кількості
запусків на акаунт (daily run cap), token/metered overage; опубліковані
цифри вартості/часу — невідомо на цій сторінці; ліміти — 1 подія на GitHub-
trigger породжує окрему сесію (немає перевикористання), custom cron не
частіше 1 разу/год.

## Цитата
> "Routines run autonomously as full Claude Code cloud sessions: there is no permission-mode picker and no approval prompts during a run."

## Нотатки
Прямо відповідає на "як реалізують людські гейти в unattended-агентах":
відповідь Anthropic — гейт не всередині запуску, а до (промпт) і після
(рев'ю PR/сесії). Для нашого v1 (нічні скаути) це означає: якщо будувати на
Routines/Managed Agents, "гейт evidence reviewed" з CLAUDE.md системи
довелось би реалізувати як окремий крок рев'ю після нічного прогону, а не
паузу всередині нього.
